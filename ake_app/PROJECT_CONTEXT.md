## وضعیت قابلیت‌ها در کد فعلی
- پوسته اصلی با بخش‌های خانه، فروشگاه، اخبار، سبد خرید و حساب کاربری.
- سه بنر محلی SVG در صفحه خانه؛ بدون وابستگی به URL تصاویر خارجی.
- دریافت محصولات از WooCommerce Store API و نمایش توضیحات HTML و ویژگی‌ها.
- دکمه افزودن به سبد، انتخاب تعداد، وارییشن‌های واقعی و ثبت مشخصات انتخابی.
- ورود/عضویت Digits با رمز عبور و OTP در سورس Flutter.
- پروفایل مشتری و پنل پیک متصل به API مکمل AKE.
- پنل پیک: سفارش‌های تخصیص‌یافته، اطلاعات مشتری، مسیریابی خارجی و گردش وضعیت تحویل.
- نقشه نشان: پیاده‌سازی شده، اما برای نمایش کاشی‌ها به کلید Web نشان نیاز دارد.
- افزونه مکمل وردپرس نسخه 0.2.0 در wordpress/ake-delivery.php؛ برای فعال‌شدن اصلاح Digits و API جدید باید روی سایت جایگزین شود.

## محدودیت‌های تأییدنشده
- کلید قبلی کاربر از نوع Mobile بوده و برای پکیج فعلی Neshan مناسب نیست؛ کلید Web هنوز باید ساخته و پس از نصب APK در صفحه تنظیم نقشه وارد شود؛ در Secure Storage دستگاه نگهداری می‌شود.
- فایل افزونه مکمل AKE در مخزن آماده است، اما به دلیل read-only بودن دسترسی WPVibe به فایل‌های افزونه، هنوز روی سایت زنده جایگزین نشده است.
- ثبت‌نام پیامکی، ورود واقعی، سفارش‌گذاری، تغییر وضعیت پیک و نمایش کاشی نقشه تا پس از این دو اقدام، تست عملیاتی نشده‌اند.
- در زمان بررسی API فروشگاه، ۵ محصول اول ساده بودند و endpoint نوع variable و variation خالی برگشت؛ پشتیبانی وارییشن در کد آماده شده اما در داده فعلی سایت نمونه واقعی برای تست وجود ندارد.

## قواعد شروع هر نوبت توسعه
1. ابتدا این فایل و `TROUBLESHOOTING.md` را بخوان.
2. آخرین نسخه فایل‌های موردنیاز را از شاخه `main` بگیر؛ از نسخه قدیمی محلی یا حافظه چت به‌عنوان مرجع قطعی استفاده نکن.
3. پیش از جایگزینی فایل محلی، از آن نسخه پشتیبان بگیر.
4. تغییرات را محدود به فایل‌های لازم نگه دار.
5. بعد از هر تغییر، نتیجه ساخت/اجرا را از کاربر بگیر و فقط خطاهای واقعی را اصلاح کن.
6. هر تجربه جدید، چه موفق و چه ناموفق، همان روز در `TROUBLESHOOTING.md` ثبت شود.
7. هر تغییر قابل مشاهده در برنامه در `CHANGELOG.md` ثبت شود.
8. هیچ‌گاه موفقیت اجرای برنامه یا اتصال به سرویس را بدون خروجی تأییدشده ادعا نکن.
